## მოკლედ

საიტის ტექნიკური საფუძველი კარგად არის აწყობილი: redirect-ები, canonical-ები, პაგინაცია, ფილტრების `noindex`, Product schema და პროდუქტების უნიკალური description-ები უკვე გამართულად მუშაობს.

ზრდას ხუთი რამ აფერხებს:

1. **შიდა ბმულები.** მთავარი მენიუს 8 ზედა კატეგორია (ტექნიკა, ავეჯი, სპორტი და ა.შ.) `javascript:void(0)` ბმულია, ამიტომ Google მათ ვერ მიჰყვება. მთავარ გვერდზე H1 და ტექსტი საერთოდ არ არის.
2. **კატეგორიები და ბრენდები.** 113-დან 112 კატეგორიას ერთნაირი title აქვს. 61 კატეგორიის ტექსტი 50 სიტყვაზე მოკლეა. შემოწმებული ბრენდის გვერდებიდან არცერთს არ აქვს ტექსტი.
3. **ფილტრების გვერდები.** ისეთი მოთხოვნადი ძიებებისთვის, როგორიცაა „Samsung ტელევიზორი“, „55 დიუმიანი ტელევიზორი“ ან „ინვერტორული კონდიციონერი“, საიტზე ცალკე გვერდი არ არსებობს.
4. **პროდუქტების მონაცემები.** სახელების 8%-ში ქართული სიტყვა არ არის. 12 სახელში კირილიცის ასოებია. აღწერები მხოლოდ სპეციფიკაციების სიაა, შეფასებები არ ჩანს.
5. **სიჩქარე მობილურზე.** Lighthouse-ში მთავარი გვერდის LCP 3.5 წამია, კატეგორიის LCP კი 4.9 წამი.

## რა არის უკვე კარგად (ამას ნუ შეცვლით)

- HTTPS და `www` → `superi.ge` გადამისამართება, slash-ის გარეშე URL-ები და `index.php` სწორად გადადის 301-ით.
- 386 შემოწმებულ გვერდზე canonical საკუთარ თავზე მიუთითებს. UTM პარამეტრებიანი URL-ები სუფთა მისამართზე canonical-დება, `?page=2` კი `/page-2/`-ზე.
- პაგინაციის გვერდებს საკუთარი canonical აქვთ, title-ში კი „გვერდი N“ ემატება.
- დახარისხება, ფილტრები და ძიება `noindex`-ზეა და robots.txt-შიც დაბლოკილია, ასე რომ Google ზედმეტ გვერდებზე დროს არ ხარჯავს.
- ყველა შიდა გვერდს ზუსტად ერთი H1 აქვს.
- ყველა პროდუქტზე არის Product, Offer და BreadcrumbList schema. მთავარ გვერდზე არის Organization, WebSite და დაბრუნების პოლიტიკა.
- პროდუქტების meta description-ების 83% უნიკალურია.
- სურათები WebP ფორმატშია, აქვთ width/height და alt. alt-ის გარეშე სურათი არ ვიპოვე.
- არარსებული გვერდი სწორ 404 სტატუსს აბრუნებს. სურათების sitemap-ში 33 000-ზე მეტი სურათია.
- ზოგ კატეგორიას უკვე ძლიერი ტექსტი აქვს: `/televizorebi/`, `/mobiluri-teleponebi/`, `/kompresorebi/`, `/xelis-traqtorebi/`, `/gazis-gamatboblebi/`. ესენი დანარჩენი კატეგორიებისთვის ნიმუშად გამოდგება.

## 1. მთავარი მენიუ: 8 კატეგორია Google-ისთვის უხილავია (P1)

**რა ვნახე**
- მენიუს ზედა დონის 8 პუნქტს `href="javascript:void(0)"` აქვს: ტექნიკა, საბავშვო პროდუქცია, სახლი და სილამაზე, სპორტი და დასვენება, ბაღი და ეზო, სამშენებლო ხელსაწყოები, ცხოველთა სამყარო, ავეჯი. ასეთივეა 5 „სრულად“ ბმული.
- ამ კატეგორიების გვერდები არსებობს და sitemap-შიც არის (`/teqnika/`, `/sabavshvo-produqtsia/`, `/sakhli-da-dekori/`, `/sporti/`, `/baghi-da-ezo/`, `/samsheneblo-khelsatskoebi/`, `/tskhovelta-samkaro/`, `/aveji/`), მაგრამ მენიუდან მათზე ბმული არ მიდის.
- Lighthouse SEO-მაც იგივე დააფიქსირა: „Links are not crawlable“.
- sitemap-ის 15 კატეგორიაზე მთავარი გვერდიდან საერთოდ არ მიდის ბმული: `teqnika`, `sabavshvo-produqtsia`, `sakhli-da-dekori`, `samsheneblo-khelsatskoebi`, `tskhovelta-samkaro`, `baghi-da-ezo`, `saburavebi`, `portatuli-damtenebi`, `proeqtoris-ekranebi`, `akumulatorebi`, `avtosamkaro`, `proeqtori`, `motherboard`, `protsesorebi`, `mausebi`.

**რატომ არის მნიშვნელოვანი**
ზედა კატეგორიები ყველაზე ფართო ძიებებს პასუხობს („ტექნიკა“, „ავეჯი“, „ბაღის ინვენტარი“). საიტის შიდა „ავტორიტეტის“ დიდი ნაწილი სწორედ მენიუდან მიედინება. Google `javascript:` ბმულს არ მიჰყვება.

**რა გავაკეთოთ**
1. UniTheme2-ის მენიუში (Design → Menus) თითოეულ ზედა პუნქტს კატეგორიის URL მივუთითოთ. „სრულად“ კატეგორიის გვერდზე უნდა გადადიოდეს.
2. თუ მობილურზე პირველი შეხებით მენიუ უნდა იხსნებოდეს, ეს ქცევა დავტოვოთ, მაგრამ ტექსტი მაინც `<a href="...">` იყოს.
3. მენიუში ან მშობელი კატეგორიის გვერდზე დავამატოთ ბმულები, რომლებიც ახლა არ ჩანს: საბურავები, აკუმულატორები, ავტოსამყარო, პორტატული დამტენები, პროექტორის ეკრანები, დედა დაფები, პროცესორები, მაუსები.

## 2. მთავარი გვერდი: არ აქვს H1, H2 და ტექსტი (P1)

**რა ვნახე**
- H1, H2 და H3 მთავარ გვერდზე საერთოდ არ არის, არც საწყის HTML-ში და არც რენდერის შემდეგ.
- გვერდზე ~370 სიტყვაა და თითქმის ყველა მენიუდან მოდის.
- 20 ბლოკი (პროდუქტები, ბანერები) AJAX-ით იტვირთება (`dispatch=block_manager.render`) მხოლოდ მაშინ, როცა ეკრანზე გამოჩნდება.
- Chromium-ში Googlebot-ის user-agent-ით 6 წამის შემდეგ 20-დან 13 ბლოკი ჩაიტვირთა, 7 არა.
- Title კარგია (61 სიმბოლო). Description 200 სიმბოლოა და შედეგებში მოიჭრება.
- სამუშაო საათები არ ემთხვევა: schema-ში წერია ორშ–შაბ 10:00–21:00, footer-ში კი ორშ–კვი 9:00–21:00.

**რა გავაკეთოთ**
1. **H1** (შეიძლება დიზაინით პატარა იყოს, მაგრამ ხილული): `ტექნიკისა და ელექტრონიკის ონლაინ მაღაზია`
2. ბლოკების სათაურები **H2**-ით: „ფასდაკლებული პროდუქცია“, „პოპულარული“, „ყველაზე გაყიდვადი“, „ჩვენ გირჩევთ“, „პოპულარული კატეგორიები“. ახლა ეს `div`/`span`-ებია.
3. პირველი პროდუქტების ბლოკისთვის AJAX ჩატვირთვა გამოვრთოთ (UniTheme2-ის ბლოკის პარამეტრებში), რომ პროდუქტები და მათი ბმულები საწყის HTML-ში იყოს. დანარჩენი ბლოკები შეიძლება AJAX-ით დარჩეს.
4. გვერდის ბოლოში დავამატოთ SEO ტექსტი (პროექტი ქვემოთაა).

## 6. ფილტრების SEO გვერდები: ზრდის ყველაზე დიდი რეზერვი (P2)

**რა ვნახე**

**რა გავაკეთოთ**

**მიზეზები და გამოსწორება**
1. **მობილურის LCP ბანერია.** ის CSS `background-image`-ით იტვირთება, ბრაუზერი მას გვიან პოულობს და preload-ის სიაში არ არის.

   - **გამოსწორება:** პირველი ბანერი იყოს `<img>` ან `<picture>` (mobile/desktop წყაროებით), `fetchpriority="high"`-ით და lazy-load-ის გარეშე. Preload-ს `media` ატრიბუტი მივცეთ, ლოგოს preload კი ამოვიღოთ.
2. **კატეგორიის LCP პირველი პროდუქტის სურათია.** პირველი 2–4 სურათი lazy-load-ის გარეშე, `fetchpriority="high"`-ით უნდა ჩაიტვირთოს.
3. **JavaScript:** მთავარი JS ფაილი ~1.1 MB-ია (შეკუმშვამდე). Lighthouse-ის შეფასებით ~187 KB JS გვერდზე არ გამოიყენება. TBT 300–610 მწმ-ია.
   - გამოუყენებელი add-on-ები გამოვრთოთ.
   - არაკრიტიკული სკრიპტები `defer`-ით ჩავტვირთოთ.
4. **DOM-ის ზომა:** მენიუ და ფილტრები ყველა გვერდზე ათასობით ელემენტს ამატებს. მენიუს ქვედა დონეები შეიძლება მომხმარებლის ქმედებაზე ჩაიტვირთოს.
5. **HTML cache:** HTML საერთოდ არ კეშირდება (`cache-control: no-store`, `cf-cache-status: DYNAMIC`). სტუმრებისთვის (ავტორიზაციისა და კალათის გარეშე) ჩავრთოთ full-page cache LiteSpeed-ში ან Cloudflare-ის cache rule-ით. ეს TTFB-ს შეამცირებს.
6. **საველე მონაცემები:** რეალური მომხმარებლების მონაცემები (CrUX) აქედან ვერ მივიღე. გადახედეთ Search Console → Core Web Vitals რეპორტს.
